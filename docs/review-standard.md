# Aria 代码审查标准

本文是审查 Aria 改动时逐条核对的标准. 审查依据依次是 docs/architecture.md, 现有实现与测试的行为, 以及本文. 三者冲突时以 architecture.md 为准, 并在审查结论中指出冲突.

## 1. 审查的输出格式

审查结论写成一份 Markdown 文件, 每个问题单独成条, 每条包含以下内容.

1. 严重程度: 阻断, 重要或建议. 阻断指行为错误, 安全问题, 数据损坏, 测试缺失导致关键行为未被验证, 或违反 architecture.md; 重要指边界条件, 资源泄漏, 可维护性明显受损; 建议指不影响正确性的改进.
2. 位置: 文件路径与行号.
3. 问题: 说明代码现在做什么, 应该做什么, 依据是 architecture.md 的哪一节或哪个已有实现与测试.
4. 失败场景: 给出能触发问题的具体输入或状态, 以及错误的输出.

没有发现问题的审查项也要列出, 写明已经核对过的内容, 不能只写通过. 审查者不得修改代码.

## 2. 行为一致性

1. 每个模块的行为与 docs/architecture.md 及现有测试描述的行为一致, 核对分支, 默认值, 常量, 错误信息, 状态码, 日志内容与边界条件.
2. 与 architecture.md 第 7 节列出的既有差异不同, 又改变了对外行为的地方, 必须有依据并同步更新 architecture.md, 否则视为阻断问题.
3. JSON 处理: 透传字段必须保持原始取值, 不能经过会丢失字段或改变数值精度的结构体. 表示整数的数值不能变成浮点数.
4. 时间与计时: 超时, 重试等待, 空闲看门狗与预算计时的起点和重置条件要符合 architecture.md 的描述.
5. 并发语义: 账号池的游标推进, 会话固定的淘汰顺序, 刷新时的加锁范围, 写回失败时的处理, 都要符合 architecture.md 的描述.

## 3. 正确性与鲁棒性

1. 非测试代码不得使用 unwrap, 不得在可能失败的地方使用 expect. 确实不会失败的 expect 必须在旁边注释说明原因.
2. 不得出现 panic, 数组越界和整数溢出的可能. 算术溢出要用 checked 运算处理, 例如 i64 之上界用 checked 运算而不是直接相加.
3. 异步代码中不得调用阻塞的文件或网络操作, 除非放在 spawn_blocking 中. 持有 std::sync::Mutex 时不得跨越 await.
4. 所有从网络或文件读取的数据都要有上限.
5. 客户端断开, 上游断开, 上游超时, 凭据文件缺失或损坏, 刷新失败, 写回失败, 磁盘写入失败, 这些情况都要有明确的处理和测试.
6. 文件写入必须原子发布, 权限为 0600.

## 4. 安全

1. 日志, 错误信息和响应体中不得出现密钥, 令牌, 请求体, 响应体和带查询串的上游地址.
2. 客户端密钥比对必须是常量时间且比较完所有密钥.
3. 上游地址只能来自配置, 请求不能指定上游.
4. 登录命令的回调只监听 127.0.0.1, 必须校验 state, 输出文件不能覆盖已有文件或受保护的账号池.

## 5. 代码质量

1. 代码风格与仓库已有代码一致, 通过 cargo fmt.
2. cargo clippy --all-targets -- -D warnings 没有警告. 不得用 allow 属性压制警告, 除非注释说明原因.
3. 不得有没有调用方的抽象, 重复实现或死代码. 已有的 aria-core 工具必须复用.
4. 注释说明设计原因, 约束与非直观的逻辑, 不复述代码字面含义. 公开项, 复杂算法, 状态流转与兼容逻辑必须有注释. 注释采用中文段落在前, 英文段落在后的双语格式, 与 Canto 和 Lyra 一致.
5. 函数保持单一职责, 状态机用枚举表达, 不用多个布尔字段组合表示互斥状态.
6. 新增依赖必须在根目录 Cargo.toml 的 workspace.dependencies 中声明, 并且是成熟且广泛使用的库.

## 6. 测试

1. 每个新行为或改动行为都有对应的 Rust 测试. 缺少对应测试时, 交付说明必须列出并说明原因.
2. 测试断言具体结果, 不能只断言没有出错. 流式输出要断言完整的事件序列.
3. 测试只能访问回环地址上的桩服务, 不读取本机真实凭据, 不依赖执行顺序或真实时间的长等待. 计时相关测试用可控的短预算.
4. 测试不得喧宾夺主: 不为私有的简单访问器写测试, 不重复测试同一行为.

## 7. 交付说明

实现者的交付说明需要包含: 修改的文件, 主要决定及理由, 行为与测试的对应关系, 已经执行的命令及其结果, 未解决的问题. 审查者核对交付说明与代码是否一致.
